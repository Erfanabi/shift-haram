# شیفت‌بندی هوشمند خادمان (مدل ناحیه‌محور)

اپلیکیشن React Native (Expo + TypeScript + NativeWind) برای تولید خودکار «لوح خدمت» کشیک،
بر پایه‌ی سند سناریو در `docs/`.

## اجرا

```bash
npm start            # Expo dev server
npm run ios          # iOS
npm run android      # Android
npm run web          # مرورگر
npm test             # تست‌های موتور و خروجی چاپی
npm run typecheck    # بررسی تایپ
```

## معماری

| مسیر | نقش |
|---|---|
| `src/domain/` | مدل دامنه و داده‌ی اولیه (برگرفته از لوح کشیک ششم) |
| `src/engine/` | موتور چیدمان دوفازی + اعتبارسنج قوانین سخت |
| `src/store/` | وضعیت ماندگار (Zustand + AsyncStorage) |
| `src/app/` | صفحه‌ها (Expo Router) |
| `src/components/` | ماتریس لوح، کارت خادم و اجزای مشترک |
| `src/export/` | بازسازی لوح سنتی به HTML و خروجی PDF |

### موتور چیدمان (`src/engine`)

مسئله مانند یک مسئله‌ی ارضای قید مدل شده و در دو فاز حل می‌شود:

- **فاز ۱ — `phase1ZoneAssignment.ts`**: تخصیص هر خادم به دقیقاً یک منطقه و قفل کردن آن
  («تثبیت جغرافیایی»)، متناسب با تقاضای هر منطقه و با توازن پیشکسوت/تازه‌کار و پخش تأخیری‌ها.
- **فاز ۲ — `phase2Rotation.ts`**: چرخش درون هر منطقه به‌صورت ایزوله؛ ساخت حریصانه
  (اولویت با پست‌های حیاتی و پرسختی) و سپس بهبود با تپه‌نوردی روی تابع هدف `objective.ts`.

خروجی با seed ثابت **قطعی و تکرارپذیر** است.

#### قوانین سخت (هرگز نقض نمی‌شوند)

۱. تثبیت جغرافیایی ۲. عدم تداخل زمانی ۳. پوشش کامل پست‌های حیاتی
۴. سقف دو بازه‌ی متوالی بدون استراحت ۵. حذف غایبان (و تأخیری‌ها پیش از ساعت ورود)
۶. ترکیب تجربه در پست‌های حساس

اگر جواب ممکنی نباشد، به‌جای خروجی ناقص، `shortages` دقیقاً می‌گوید کدام پست در کدام بازه و
با کمبود چند نفر پر نشده است؛ پست‌های شناور خالی می‌مانند و حیاتی‌ها حفظ می‌شوند.

#### قوانین نرم (در تابع هدف وزن‌دار)

عدالت در سختی پست (با احتساب سابقه‌ی کشیک‌های قبلی)، چرخش مکانی درون منطقه،
توازن استراحت حول نماز، و توازن پیشکسوتان بین مناطق. خروجی به‌صورت «شاخص عدالت ٪» نمایش داده می‌شود.

### ویرایش دستی

`validate.ts` تنها مرجع حقیقت است و هر دو مسیر ویرایش از آن عبور می‌کنند:

- **Tap-to-swap** (پیش‌فرض): لمس کارت ⇒ خانه‌های مجاز سبز می‌شوند و کل مسیر روزانه‌ی همان خادم
  هایلایت می‌شود؛ لمس مقصد ⇒ جابه‌جایی یا تعویض.
- **درگ‌اندراپ**: نگه‌داشتن کارت ⇒ کارت شناور می‌شود و drop zoneهای مجاز می‌درخشند؛ رها کردن
  روی خانه‌ی نامجاز ⇒ پیام دلیل و بازگشت کارت.

تصمیم نهایی همیشه با سرگروه است؛ سیستم فقط نگهبان قوانین است.

## محدوده‌ی فعلی

نقش‌های **سرگروه** و **مدیر گروه** پیاده شده‌اند. اعلام حضور از صفحه‌ی حضوروغیاب سرگروه وارد
می‌شود (پنل شخصی خادم و عملیات روز کشیک در فازهای بعدی سند).
